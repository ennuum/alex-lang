# json

Analyse et sérialisation JSON (RFC 8259) en ALEX pur. Aucune dépendance native (hors io pour load/save).

```alex
use json
v := json.parse("{\"nom\": \"Alex\", \"tags\": [1, 2.5, true, null]}")
print(v["nom"], v["tags"][1])            # Alex 2.5
print(json.stringify(v))                 # {"nom":"Alex","tags":[1,2.5,true,null]}
print(json.pretty(v))                    # indenté de 2 espaces

```
CORRESPONDANCE DES TYPES
```alex
null <-> null   true/false <-> bool   entier <-> int   nombre à fraction/exposant <-> float
chaîne <-> str  tableau <-> list (un tuple est sérialisé comme tableau)   objet <-> dict

```
ERREURS
```alex
Toute erreur lève raise("JSONError", message). Pour parse, le message contient « ligne L, colonne C ».
stringify refuse : clés de dict non str, nan/inf, valeurs non JSON (fonction, instance...), profondeur > 100 niveaux
(ce qui détecte aussi les structures cycliques). Les caractères de contrôle sont échappés : \n \t \r \b \f ou \u00XX.

```
LIMITES CONNUES
```alex
- \uXXXX est décodé pour tout le plan Unicode (string.chr), paires de substitution UTF-16 (\uD83D\uDE00) comprises ;
  une moitié de paire isolée lève JSONError.
- str(float) du runtime ne garantit pas l'aller-retour exact (15 chiffres significatifs).
- Les dicts itèrent dans l'ordre d'insertion ; stringify trie les clés par défaut (sort_keys=true), sort_keys=false garde cet ordre.
```

# os

Architecture
```alex
os.al          API publique ALEX + logique de haut niveau (chemins,
               copie / déplacement / suppression récursifs, normalisation,
               conversions de modes, system_info, terminal...).
_native_os     primitives qui dépendent RÉELLEMENT de l'OS (runtime C++ :
               runtime/native/os/). Backends POSIX et Windows séparés.

```
Permissions : ce sont celles du système d'exploitation. Aucune sandbox
artificielle n'est ajoutée par le langage : une opération refusée par l'OS
lève IoError, une opération permise par l'OS réussit.

Erreurs
```alex
IoError        l'OS refuse ou ne peut pas faire l'opération.
TypeError      argument d'un mauvais type.
ArgumentError  argument de bon type mais invalide (pid <= 0, mode hors limites...).

```
Conventions
```alex
- Les temps (time, mtime, atime, ctime) sont des float : secondes depuis
  l'epoch Unix. monotonic_time() est en secondes depuis une origine
  arbitraire.
- Les noms commençant par `_` sont des détails d'implémentation (le
  langage n'a pas de visibilité privée) : ne pas en dépendre.
- Les paramètres optionnels valent `null` par défaut (le langage ne
  supporte pas d'autres valeurs par défaut).
```

# compiler.bc_parser

Analyseur syntaxique de la chaîne de compilation vers bytecode : portage fidèle de src/Parser.cpp. Il produit
l'arbre de compiler.bc_ast avec exactement les mêmes nœuds, positions et désucrages que le parser de
référence : décorateurs (f = déco(f) après la définition), fonctions fléchées et lambdas ({ return expr }),
tranches (__slice), ensembles (__make_set), déstructuration (__dN, __len, raise ValueError), for a, b in
(__forN), with (__withN + try/finally), assert, del (__del_item), pass, extend, comparaisons chaînées.
Les compteurs __forN / __dN / __withN sont globaux au processus, comme les « static int » du C++.

```alex
use compiler.bc_parser as bp
prog := bp.parse_file("prog.al")               # Node « Program »
prog2 := bp.parse_text("x := 1\nprint(x)\n", "essai.al")

```
Erreurs : SyntaxError (« fichier:ligne:colonne: message »), et celles du lexer (compiler.bc_lexer).
